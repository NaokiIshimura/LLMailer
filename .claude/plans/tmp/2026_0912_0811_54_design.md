### レイヤーの責務

| レイヤー | 責務 | 備考 |
| --- | --- | --- |
| `components/` | 表示のみ。状態を持たず props を受け取る | Props は `readonly` |
| `hooks/` | 取得・送信・選択などのロジックと状態 | UI から分離 |

| `lib/llm/` | Anthropic SDK 呼び出し | サーバー専用 |

## 2. 技術選定と理由

| 項目 | 選定 | 理由 |
| --- | --- | --- |
| フレームワーク | Next.js 15 / App Router | UI と API を1プロジェクトで完結。Server 専用コードを `app/api` に隔離できる |
| 言語 | TypeScript（strict） | 型安全。Anthropic SDK の型をそのまま使う |
| LLM SDK | `@anthropic-ai/sdk` | 公式 SDK。`messages.create` を利用 |
| モデル | `claude-opus-5` | 既定モデル。エージェント単位で上書き可 |
| 永続化 | JSON ファイル（`node:fs/promises`） | 初期スコープを軽量に保つ。将来 SQLite へ差し替え可能なリポジトリ境界を用意 |
| 状態管理 | React hooks + `fetch` | 追加ライブラリ不要な規模 |
| スタイル | CSS Modules | 依存を増やさず3ペインを組める |
| ID 生成 | `node:crypto` の `randomUUID` | 追加依存なし |

## 3. データモデル

`src/types/mail.ts` に定義する。

```ts
/** 自分（ユーザー）のアドレス */
export const ME_ADDRESS = 'me@llmailer.local';

/** 宛先となる AI エージェント */
export interface Agent {
  readonly address: string;      // 例: "opus@llmailer.local"
  readonly name: string;         // 例: "Opus（汎用）"
  readonly model: string;        // 例: "claude-opus-5"
  readonly systemPrompt?: string;
  readonly description?: string;
}

/** メッセージの配信状態 */
export type MessageStatus =
  | 'draft'     // 下書き
  | 'sent'      // 送信済み（ユーザー発）
  | 'pending'   // 配信中（LLM 応答待ちのプレースホルダ）
  | 'received'  // 受信（LLM 応答）
  | 'failed';   // 配信失敗

export interface Message {
  readonly id: string;
  readonly threadId: string;
  readonly from: string;          // ME_ADDRESS または Agent.address
  readonly to: readonly string[];
  readonly subject: string;
  readonly body: string;
  readonly status: MessageStatus;
  readonly createdAt: string;     // ISO 8601
  readonly inReplyTo?: string;    // 返信元 Message.id
  readonly read: boolean;         // 受信メッセージの既読フラグ
  readonly error?: string;        // status === 'failed' のときの理由
  readonly usage?: {              // 参考情報（トークン使用量）
    readonly inputTokens: number;
    readonly outputTokens: number;
  };
}

export interface Thread {
  readonly id: string;
  readonly subject: string;
  readonly participants: readonly string[];
  readonly lastMessageAt: string;
  readonly messageCount: number;
  readonly unreadCount: number;
  readonly snippet: string;       // 最新メッセージ本文の冒頭
  readonly hasPending: boolean;   // 配信中のメッセージを含むか
  readonly hasFailure: boolean;
}
```

`Thread` は保存せず、`Message[]` から導出する（単一の真実の source を `Message` に置く）。

### 既定のエージェント（`data/agents.json` の初期値）

| アドレス | 名前 | モデル | システムプロンプト |
| --- | --- | --- | --- |
| `opus@llmailer.local` | Opus（汎用） | `claude-opus-5` | 日本語で簡潔に答える汎用アシスタント |
| `haiku@llmailer.local` | Haiku（高速） | `claude-haiku-4-5` | 短時間で要点だけ返す |
| `reviewer@llmailer.local` | コードレビュアー | `claude-opus-5` | コードの問題点を指摘する |
| `translator@llmailer.local` | 翻訳担当 | `claude-opus-5` | 日英翻訳のみを返す |

### フォルダの定義（保存せず導出）

| フォルダ | 条件 |
| --- | --- |
| 受信箱 | `status === 'received' or 'pending' or 'failed'` を含むスレッド |
| 送信済み | `status === 'sent'` を含むスレッド |
| 下書き | `status === 'draft'` のメッセージ |
| 全件 | すべてのスレッド |

## 4. API 仕様

すべて JSON。エラーは `{ "error": { "message": string } }` と HTTP ステータスで返す。

| メソッド | パス | 用途 | リクエスト | レスポンス |
| --- | --- | --- | --- | --- |
| GET | `/api/agents` | エージェント一覧 | - | `{ agents: Agent[] }` |
| GET | `/api/threads?folder=inbox\|sent\|drafts\|all&q=` | スレッド一覧 | - | `{ threads: Thread[] }` |
| GET | `/api/threads/[id]` | スレッド詳細 | - | `{ thread: Thread, messages: Message[] }` |
| PATCH | `/api/threads/[id]` | 既読化 | `{ read: true }` | `{ thread: Thread }` |
| POST | `/api/messages` | 送信（＋LLM 応答生成） | `SendMessageRequest` | `{ sent: Message, replies: Message[] }` |
| POST | `/api/messages/drafts` | 下書き保存 | `{ to, subject, body, id? }` | `{ draft: Message }` |
| DELETE | `/api/messages/[id]` | 下書き削除 | - | `204` |

### `POST /api/messages`

```ts
interface SendMessageRequest {
  readonly to: readonly string[];   // 1件以上。既知の Agent.address のみ許可
  readonly subject: string;         // 空文字は "(件名なし)" に補正
  readonly body: string;            // 必須
  readonly threadId?: string;       // 返信時に指定
  readonly inReplyTo?: string;
  readonly draftId?: string;        // 下書きから送る場合は送信後に削除
}
```

処理順序:

1. 入力検証（`to` が既知エージェントか、`body` が非空か）
2. `threadId` 未指定なら新規スレッド ID を発行
3. ユーザー発メッセージを `status: 'sent'` で保存
4. 宛先ごとに `Promise.allSettled` で `transport.deliver()` を並行実行
5. 成功は `status: 'received'`、失敗は `status: 'failed'` + `error` で保存
6. `{ sent, replies }` を返す

同期的に応答を待つため、クライアントはこの間ローダーを表示する（FR-09）。

## 5. LLM 呼び出し仕様

`src/lib/llm/client.ts`

```ts
import Anthropic from '@anthropic-ai/sdk';

const client = new Anthropic(); // ANTHROPIC_API_KEY を環境から解決
```

`src/lib/transport/llmTransport.ts`

- 会話履歴の組み立て: スレッド内のメッセージを時刻順に並べ、
  - `from === ME_ADDRESS` → `{ role: 'user' }`
  - `from === 宛先エージェント` → `{ role: 'assistant' }`
  - 他エージェントの発言は `user` ロールに `【<name> の回答】` を付けて畳み込む（マルチ宛先スレッドで役割が壊れないようにする）
  - `status: 'pending' | 'failed' | 'draft'` のメッセージは履歴から除外
- リクエストパラメータ:

```ts
const response = await client.beta.messages.create({
  model: agent.model,                    // 既定 'claude-opus-5'
  max_tokens: 16000,                     // 非ストリーミングの既定値
  system: buildSystemPrompt(agent, subject),
  messages: history,
  betas: ['server-side-fallback-2026-07-01'],
  // @ts-expect-error SDK の型が fallbacks に未追従のため
  fallbacks: 'default',                  // refusal 時のサーバー側フォールバック
});
```

- `thinking` は指定しない（`claude-opus-5` は既定で adaptive）
- `budget_tokens` / `temperature` / assistant prefill は使用しない（`claude-opus-5` では 400）
- `response.stop_reason === 'refusal'` の場合は `content` を読まず、`stop_details` を理由として `failed` にする
- `content` は判別共用体なので `block.type === 'text'` で絞り込んでから `text` を連結する
- エラーは SDK の型付き例外で分類する（`NotFoundError` → `RateLimitError` → `APIStatusError` → `APIConnectionError` の順に具体的なものから捕捉）

### システムプロンプト

```
あなたはメールクライアント "LLMailer" 上のエージェント「<name>」です。
ユーザーからのメールに対し、メールの返信として自然な日本語で答えてください。
件名: <subject>
<agent.systemPrompt>
```

### Transport 抽象（実メール連携への差し替え口）

```ts
export interface Transport {
  /** 宛先へメッセージを配信し、返信メッセージ（本文とトークン使用量）を得る */
  deliver(input: DeliverInput): Promise<DeliverResult>;
}
```

`LlmTransport` が既定実装。将来の `MailTransport`（SMTP/IMAP）は同じインターフェースを満たす。

### 状態表示

| 状態 | 表示 |
| --- | --- |
| `pending` | 「配信中…」＋スピナー |
| `failed` | 赤帯で「配信に失敗しました: <理由>」＋再送ボタン |
| 未読 | スレッド一覧に `●` と件数バッジ |

### ローダー方針（FR-09）

- `useSendMessage` が保持する進行中リクエスト数が 1 以上の間、`GlobalLoader` を表示
- 送信ボタンは押下中 disabled にし、二重送信を防ぐ
- 成功・失敗いずれでもカウンタを減算する（`finally`）

## 8. セキュリティ考慮事項

| 項目 | 対応 |
| --- | --- |
| API キー | サーバー専用モジュール（`lib/llm`）のみで参照。`NEXT_PUBLIC_` 接頭辞は使わない |
| 入力検証 | `to` は `agents.json` に存在するアドレスのみ許可。未知アドレスは 400 |
| プロンプトインジェクション | LLM の応答は本文テキストとして表示するのみ（HTML として解釈しない）。`dangerouslySetInnerHTML` は使わない |
| パストラバーサル | store のファイルパスは定数。リクエスト値からパスを組み立てない |
| データ流出 | 送信先は Claude API のみ。他の外部サービスへは送らない |
| 保存データ | `data/messages.json` は `.gitignore` に含め、会話内容をコミットしない |
