# LLMailer 実行計画

## 1. 実装の概要

メーラーの UI メタファーで Claude に指示を送るアプリ「LLMailer」を、Next.js（App Router）+ TypeScript で新規に構築する。
宛先を AI エージェント、件名をスレッドのお題、本文を指示、返信を LLM の応答として扱う。
永続化は JSON ファイル、LLM は Claude API（`claude-opus-5`）。送受信処理は `Transport` インターフェース越しに呼び出し、将来の実メール連携に備える。

関連ドキュメント:

- 要件定義: `2026_0912_0810_32_requirements.md`
- 設計: `2026_0912_0811_54_design.md`
- タスク: 同ディレクトリの `*_tasks.md`

## 2. ステップバイステップの実行計画

### STEP 1 プロジェクト初期化（TASK-001〜003）

1. `npx create-next-app@latest llmailer --ts --app --no-tailwind --eslint --src-dir --import-alias "@/*"` で生成
2. サンプルページ・不要アセットを削除
3. `npm i @anthropic-ai/sdk`
4. `.env.local.example` と `.gitignore`（`data/messages.json`）を整備
5. `src/types/mail.ts` に型を定義

### STEP 2 永続化層（TASK-004〜007）

1. `lib/store/jsonFile.ts`: 読み込み（未存在なら既定値で作成）と書き込みの直列化
2. `lib/store/agentRepository.ts`: 既定エージェント4件をシード
3. `lib/store/messageRepository.ts`: CRUD と既読化
4. `lib/thread.ts`: `Message[]` からの `Thread[]` 導出、フォルダ絞り込み、検索

### STEP 3 LLM 配信層（TASK-008〜011）

1. `lib/llm/client.ts`: `new Anthropic()`（API キーは環境から解決）
2. `lib/llm/prompt.ts`: システムプロンプト生成、会話履歴変換
3. `lib/transport/types.ts`: `Transport` 抽象
4. `lib/transport/llmTransport.ts`: `client.beta.messages.create`、`refusal` 処理、例外分類

### STEP 4 API 層（TASK-012〜016）

1. 読み取り系（`/api/agents`, `/api/threads`, `/api/threads/[id]`）
2. 送信系（`POST /api/messages`）: 検証 → 保存 → 並行配信 → 結果保存
3. 下書き系

### STEP 5 UI 層（TASK-017〜025）

1. `globals.css` で3ペインのグリッドと配色
2. `Loader` を先に用意し、以降の hooks から利用
3. hooks（取得・送信・作成状態）を実装
4. 表示コンポーネント（`FolderSidebar` → `ThreadList` → `MessageItem` → `ThreadView` → `ComposeWindow`）
5. `Mailbox` で組み立て、`app/page.tsx` から利用

### STEP 6 仕上げ（TASK-026〜029）

1. 検索 UI
2. `npm run build` と実起動での疎通確認、受け入れ基準の確認
3. README
4. 周辺コードに合わせたリファクタリング

## 4. 検証手順

1. `cp .env.local.example .env.local` して `ANTHROPIC_API_KEY` を設定
2. `npm run dev` → `http://localhost:3000`
3. AC-01: 3ペインの UI が表示される
4. AC-05: 作成 → 送信でローダーが出て、完了で消える
5. AC-02: Claude の応答が受信メッセージとして追加される
6. AC-03: 宛先を2件にして送信し、返信が2件届く
7. AC-04: スレッド内で返信し、文脈が引き継がれている
8. AC-08: 未読件数の表示と、スレッドを開いたときの既読化
9. AC-07: リロード後もデータが残る
10. AC-06: `ANTHROPIC_API_KEY` を外して送信し、配信失敗通知が出る（クラッシュしない）
11. `npm run build` が成功する

## 5. 注意点・リスク

| 区分 | 内容 | 対応 |
| --- | --- | --- |
| リスク | `POST /api/messages` が LLM 応答を同期的に待つため、応答が遅いとリクエストが長時間保持される | `max_tokens: 16000` にとどめ、将来は SSE へ移行（TASK-101） |
| リスク | マルチ宛先スレッドの会話履歴は、Claude の `user`/`assistant` 交替に素直に写像できない | 他エージェントの発言は `user` ロールに `【<name> の回答】` として畳み込む |
| リスク | JSON ファイルの同時書き込みによる破損 | 書き込みを直列化するミューテックスを `jsonFile.ts` に実装 |
| 注意 | `claude-opus-5` では `budget_tokens` / `temperature` / assistant prefill が 400 になる | 指定しない。`thinking` は省略（既定で adaptive） |
| 注意 | `stop_reason: 'refusal'` は HTTP 200 で返る | `content` を読む前に `stop_reason` を確認し、`failed` として扱う |
| 注意 | `response.content` は判別共用体 | `block.type === 'text'` で絞り込んでから `text` を参照 |
| 注意 | API キーをクライアントへ漏らさない | `lib/llm` はサーバー専用。`NEXT_PUBLIC_` は使わない |
| 注意 | 会話内容の誤コミット | `data/messages.json` を `.gitignore` に追加 |
